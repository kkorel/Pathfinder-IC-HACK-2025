# Pathfinder AI

Pathfinder AI is a web app that turns a decision you are weighing into a branching tree of clarifying questions and likely future scenarios, generated by Claude.

Big decisions are hard to think through because every choice opens onto further choices. Pathfinder makes that structure explicit: you describe the decision, answer a few short questions about it, and get two to four plausible next scenarios, each of which you can open and explore the same way. It is for anyone facing a personal or professional decision, from when to go to sleep to whether to found a startup. It was built at IC Hack 2025, the student-run hackathon at Imperial College London.

## Quickstart

You need Node.js with npm, a PostgreSQL database you can connect to, and an Anthropic API key.

Clone the repo and install the pinned dependencies:

```bash
git clone https://github.com/kkorel/Pathfinder-IC-HACK-2025.git
cd Pathfinder-IC-HACK-2025
npm ci
```

Create the two tables the app reads and writes:

```sql
CREATE TABLE scenarios (
  id UUID PRIMARY KEY,
  title TEXT,
  description TEXT,
  question_ids UUID[],
  scenario_ids UUID[],
  parent_scenario_id UUID
);

CREATE TABLE questions (
  id UUID PRIMARY KEY,
  title TEXT,
  description TEXT,
  user_answer TEXT
);
```

Create a `.env.local` file in the repo root with your credentials. Next.js loads it on startup:

```bash
CLAUDE_API_KEY=your-anthropic-api-key
POSTGRES_URL=postgres://user:password@localhost:5432/pathfinder
```

Start the development server and open http://localhost:3000:

```bash
npm run dev
```

## Usage

### Start a decision

On the home page, type your decision into the box and press Submit, or click one of the three example prompts. The app asks Claude for two to four clarifying questions, stores the decision as the root node of a new tree, and opens that node at a URL of the form `/<scenario-id>`.

### Answer the questions and generate scenarios

The right-hand panel shows one card per question. Fill in every card and press Submit. The app saves your answers, sends Claude the whole path from the root node with every question and answer along it, and asks for two to four likely future scenarios that follow. They appear as cards under the current node. Once submitted, the answers for that node are locked.

### Explore a branch

Click a scenario card to make it the current node. Pathfinder asks Claude for a fresh set of questions about that scenario. The up arrow returns to the parent node, the pencil icon starts a new decision, and the breadcrumb trail at the bottom of the page jumps to any node on the path from the root. Every node keeps its own URL, so you can return to any point in the tree later:

```text
http://localhost:3000/<scenario-id>
```

## Configuration

Both variables are read from `process.env` on the server. Neither has a default.

| Variable | Required | Default | Purpose |
| --- | --- | --- | --- |
| `CLAUDE_API_KEY` | Yes | none | Anthropic API key used by the Anthropic SDK client in `src/lib/claude.ts` |
| `POSTGRES_URL` | Yes | none | Connection string passed to the postgres.js client in `src/lib/postgres.ts` |

There are no other settings. The model (`claude-3-5-sonnet-20241022`), the 1024-token cap on each response and the two system prompts are hard-coded in `src/lib/claude.ts`.

## Development

The app is a Next.js 15 project using the App Router, React 19 and TypeScript, styled with Tailwind CSS 3 and shadcn/ui components on Radix primitives. Forms use react-hook-form with zod. Claude is called through the Anthropic TypeScript SDK and Postgres through postgres.js, with no ORM.

Two lockfiles are checked in, `package-lock.json` and `bun.lockb`. Every command in this README uses npm and `package-lock.json`.

Scripts, all defined in `package.json`:

```bash
npm run dev     # development server with Turbopack on http://localhost:3000
npm run lint    # next lint, using eslint-config-next
npm run build   # next build, which also type-checks and lints
npm start       # serve the output of npm run build on http://localhost:3000
```

There is no test suite and no CI configuration.

### How the code fits together

- `src/app/page.tsx` renders the home page: the decision box and the three example prompts.
- `src/app/[id]/page.tsx` renders a node. The node itself, its child scenarios and the question panel each stream in behind a Suspense fallback, with the breadcrumb trail below.
- `src/components/` holds the tree and form components. `src/components/ui/` holds the shadcn/ui primitives configured in `components.json`.
- `src/lib/claude.ts` holds the two system prompts and the two Claude calls, one for questions and one for scenarios.
- `src/lib/db.ts` holds every Postgres query, plus the recursive walk up `parent_scenario_id` that rebuilds the path history sent to Claude.
- `src/lib/postgres.ts` creates the postgres.js client from `POSTGRES_URL`.

Each row in `scenarios` is one node in the tree. `parent_scenario_id` points to the node above, `scenario_ids` lists the children, and `question_ids` lists the node's questions. Each row in `questions` stores one question and, once submitted, its `user_answer`. The browser never talks to the database or to Claude directly: every read and write goes through the server actions in `src/lib/db.ts`.
